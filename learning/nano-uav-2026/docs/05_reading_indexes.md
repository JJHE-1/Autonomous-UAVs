## How to evaluate a newly found project

Read the official paper/project repository before adding a performance claim. Identify the method's inputs, output semantics, training dependencies, onboard dependencies, published artifacts and tested hardware. Inspect whether "code available" means training code, evaluation code, deployment code, or only a landing page.

Record a review date and content fingerprint where available. Record the full commit and submodules for reproduction. Avoid asserting "active" solely because there are recent issues or stars. Use an explicit archival notice when available, and otherwise leave maintenance status unassessed.

Prefer fewer entries with clear evidence over a long list of unverified titles.
